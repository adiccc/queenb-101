# QueenB — האתר של הקבוצות

האתר הקיים, עם מסע, חידון, מטרות, דמויות, אווטארים, קמע ואתגרי קוד, משמש את כל הקבוצות באמצעות אותם רכיבים ועיצוב. מסך הכניסה ב־`/` מציג שבעה אזורים ואחריהם את הקבוצות של האזור. קישור ישיר כמו `/group/711` פותח את הקבוצה; מספר שאינו במיפוי מחזיר למסך הבחירה.

## הפעלה מקומית

דרישות: Node.js 22 ומעלה, חיבור לאינטרנט וחשבון Cloudflare עם גישה ל־`queenb-site-data`.

```bash
npm install
cp .dev.vars.example .dev.vars
```

יש למלא את הערכים ב־`.dev.vars` (הקובץ מוחרג מ־Git). ללא secrets מוגדרים ניתן לצפות בקבוצות, אך אימות ופעולות כתיבה/יצירה חסומים.

```bash
npx wrangler login
npm run queenb
```

הפקודה פותחת את `http://localhost:3000`. אפשר גם `npm run dev`. ההפעלה הרגילה משתמשת ב־R2 האמיתי באמצעות remote binding. להפעלה מבודדת עם אמולטור מקומי:

```bash
QUEENB_LOCAL_STORAGE=1 npm run dev
```

## מבנה הנתונים והפרדה בין קבוצות

- המיפוי המדויק נמצא ב־`lib/groups.ts`; אין קבוצה 101 במיפוי החדש.
- ה־bucket נשאר `queenb-site-data`, וה־binding בשרת הוא `QUEENB_DATA`.
- לכל קבוצה מפתח משלה: `groups/711/data.json`, `groups/513/data.json` וכן הלאה.
- API: `GET /api/groups/:groupId/data` לקריאה, `PUT` לאותו URL לשמירה מורשית. השרת מאמת את המספר מול רשימת הקבוצות, ולא משתמש במפתח שמתקבל מגוף הבקשה.
- פורמט `version: 2` כולל `data`, מפת `images` של כתובות תמונות ו־`mascotAnswers`. כל תמונה נשמרת בנפרד ב־`groups/:groupId/images/:sha256.:format`. העלאה חוזרת של אותה תמונה באותה קבוצה משתמשת באותו מפתח.
- `POST /api/groups/:groupId/images` מעלה תמונה (עד 5MB, דורש הרשאת כתיבה); `GET` לכתובת שמתקבלת קורא אותה. התמונות נגישות לצפייה כמו נתוני הקבוצה, דרך ה־Worker, ללא פתיחת ה־bucket לציבור.
- נתונים קיימים ב־`version: 1` ממשיכים להיטען. בשמירה הראשונה הלקוח מעלה את התמונות בנפרד, והשרת שומר עותק מקורי חד־פעמי ב־`groups/:groupId/legacy-v1-backup.json` לפני עדכון הנתונים. אין צורך בהרצת העברה גורפת בפרודקשן.
- שמירת הנתונים עדיין מותנית בגרסת R2. במקרה של שינוי ממחשב אחר, הלקוח מבצע מיזוג תלת־כיווני של הוספות ושינויים עצמאיים, ומנסה שוב עד שמונה פעמים. שינויים סותרים באותו שדה אינם נדרסים; ניתן להוריד גיבוי או לוותר במפורש על הטיוטה.
- לפני העלאה נשמרת טיוטה ב־IndexedDB בשם `queenb-cloud-drafts`, לפי קבוצה ולשונית, ושחזור שלה מוצע לאחר רענון באותה לשונית. הטיוטה מוסרת רק לאחר אישור שמירה בענן. אם הדפדפן חוסם אחסון, מוצגת אזהרה במקרה של כשל.
- קבצי תמונות שלא משויכים עוד לדמות וגיבויי v1 אינם נמחקים אוטומטית. הם תופסים נפח נוסף; ניתן להוסיף ניקוי מבוקר לאחר בדיקת כל ההפניות והגיבויים. מחיקת דמות מסירה אותה מהקבוצה אך לא מוחקת את קובץ התמונה.
- קבוצה שאין לה אובייקט ב־R2 נטענת מברירות המחדל הקיימות. צפייה אינה יוצרת קובץ; רק שינוי מורשה ראשון יוצר אותו.
- `group.json` הישן אינו נקרא, נכתב, נמחק או מועתק אוטומטית. גם המידע הישן ב־localStorage/IndexedDB נשאר ללא שינוי ואינו מיובא.
- הנתונים והתמונות הפעילים נמצאים בזיכרון של מופע הקבוצה בלבד. החלפת קבוצה פותחת מסמך חדש ומאפסת state, מצב מדריכה, חלוניות, טפסים, תמונות זמניות ותורי שמירה. הרשאת ה־session נשמרת בנפרד בעוגייה.
- השמירות מסודרות בתור וכוללות ETag. שינוי ממחשב אחר גורם לעצירה עם הודעה ולא לדריסה. רענון במצב זה מבטל את השינויים שלא נשמרו; יש אזהרת יציאה גם בכשל רשת. אין מיזוג שינויים אוטומטי.
- אין כפתורי ייבוא או ייצוא. עדכונים ממחשב אחר נטענים ברענון/כניסה מחדש, לא בזמן אמת. נדרש חיבור לאינטרנט; JSON כולל תמונות מוגבל ל־20MB.

## הרשאות ו־secrets

| שם | היכן מגדירים | תפקיד |
| --- | --- | --- |
| `QUEENB_ACCESS_CODE` | Worker האתר / `.dev.vars` מקומי | קוד משותף למצב מדריכה, כתיבה ויצירת תמונות. מומלץ ביטוי ארוך ולא PIN קצר. |
| `QUEENB_SESSION_SECRET` | Worker האתר / `.dev.vars` מקומי | מפתח אקראי נפרד של לפחות 32 תווים לחתימת session. |
| `IMAGE_WORKER_SECRET` | אותו ערך ב־Worker האתר וב־Worker התמונות | מפתח אקראי נפרד לתקשורת שרת־לשרת; מונע עקיפת ההרשאות דרך `/generate` הישיר. |
| `CLOUDFLARE_IMAGE_ENDPOINT` | Worker האתר / `.dev.vars`, אופציונלי | כתובת Worker התמונות, אם שונה מברירת המחדל הקיימת. |

ליצירת מפתח אקראי אפשר להריץ `openssl rand -hex 32` ולשמור את התוצאה כ־secret. יש ליצור מפתחות נפרדים ל־session ול־Worker התמונות. אין להוסיף להם קידומת `VITE_` או `NEXT_PUBLIC_`, ואין לשמור אותם בקוד.

האימות מתבצע ב־`POST /api/auth/session`. לאחר הצלחה השרת מגדיר עוגיית session חתומה ב־HMAC, עם `HttpOnly`, `SameSite=Strict` ו־`Secure` ב־HTTPS. אין קוד או token ב־localStorage. התוקף המרבי הוא שמונה שעות; העוגייה אינה מקבלת תוקף מתמשך, אך דפדפנים עם שחזור session עשויים לשמר אותה. החלפת אחד משני סודות האימות מבטלת חתימות קודמות. כפתור **נעילת גישה** במצב מדריכה מסיר את העוגייה מהדפדפן הנוכחי.

שלוש ההרשאות מוגדרות בנפרד ב־`lib/auth/permissions.ts`: `teacher:enter`, `data:write`, `images:generate`. כרגע אותו קוד מעניק את כולן בכל הקבוצות. השרת בודק הרשאה בכל כתיבה ובכל בקשת יצירה, גם בתוך routes היצירה עצמם. קיצור המקלדת `Cmd/Ctrl + Shift + T` עובר באותו אימות.

צפייה נשארת פתוחה למי שיכול לגשת לאתר; אלו אינם חשבונות נפרדים או קודים שונים לכל קבוצה. הקבצים מופרדים לפי קבוצה, וה־bucket עצמו אינו צריך להיות ציבורי. אין analytics או tracking. תמונת הפנים או תיאור המראה משמשים ליצירה בלבד; התוצאה שנשמרת לסקוואד נשמרת ב־JSON של הקבוצה.

`AUTH_RATE_LIMITER` מגביל ניסיונות כניסה ל־20 בדקה לכל IP בכל מיקום Cloudflare. הוא מוגדר ב־`vite.config.ts` באמצעות binding של Rate Limiting, namespace `101711`; חסרונו חוסם כניסה. בעת פריסה ידנית יש לשמר binding זה. מקור ההגדרות: [Cloudflare secrets](https://developers.cloudflare.com/workers/vite-plugin/reference/secrets/), [Rate Limiting binding](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/).

## לפני deploy לפרודקשן

1. הגדירי את שלושת ה־secrets ב־Worker האתר, ואת `IMAGE_WORKER_SECRET` הזהה ב־Worker התמונות. אין להשתמש בערכי בדיקה. לפריסה מה־Dashboard: Settings → Variables and Secrets → Secret. קובץ `.dev.vars` הוא מקומי בלבד ואינו מגדיר secrets בפרודקשן.
2. ודאי ש־`QUEENB_DATA` מחובר ל־`queenb-site-data` וש־`AUTH_RATE_LIMITER` מוגדר כמפורט לעיל. אין צורך ב־bucket חדש, public access, CORS, D1 או שכפול האתר. קובץ `.openai/hosting.json` אינו מחבר bucket חיצוני זה באופן אוטומטי דרך שירות Sites.
3. בני ובדקי את גרסת האתר. פרסי גם את Worker התמונות המעודכן וגם את האתר, בחלון תחזוקה קצר אם נחוץ: עד ששניהם משתמשים באותו secret יצירת התמונות עלולה להיכשל. אין בדיקת API באתר שיכולה להגן על הגרסה הישנה של Worker התמונות כל עוד היא נשארת פרוסה ופתוחה.
4. אם יש צורך במידע הישן, בחרי במפורש לאיזו קבוצה הוא שייך ובצעי את ההעתקה המתוארת בהמשך, לפני שמתחילים לערוך אותה.
5. אחרי הפריסה בדקי דרך HTTPS: כניסה עם קוד, שמירה בקבוצה ייעודית, רענון, מעבר קבוצה, ונעילת גישה. בצעי גם יצירת אווטאר/קמע אחת כדי לוודא את חיבור ה־AI עם ה־secret החדש.

לדוגמה, לאחר build אפשר להגדיר secret לאתר עם `npx wrangler secret put QUEENB_ACCESS_CODE --config dist/server/wrangler.json` (הערך מוזן בהנחיה האינטראקטיבית, לא בשורת הפקודה). באותו אופן הגדירי את שני הסודות הנוספים. ל־Worker התמונות השתמשי ב־`--config workers/flux-image-worker/wrangler.jsonc`. יש לוודא ששם ה־Worker ב־config הוא יעד הפרודקשן הרצוי לפני פקודות הפריסה.

## העברת המידע הישן — פעולה ידנית בלבד

לא בוצעה העברה אוטומטית. כדי לשייך את המידע הישן, למשל לקבוצה 711:

1. ב־Cloudflare R2 פתחי את `queenb-site-data` והורידי עותק של `group.json`. שמרי את המקור ב־bucket ללא שינוי.
2. ודאי שזה JSON במבנה `version`, `data`, `images`, `mascotAnswers` המתואר לעיל, ושזו אכן הקבוצה שאמורה לקבל אותו.
3. ודאי שהמפתח `groups/711/data.json` **אינו קיים** ושאין עריכה במקביל בקבוצה. אם כבר יש בו נתונים, עצרי: נדרש מיזוג מפורש, ולא החלפה או דריסה.
4. העלי עותק זהה בשם `data.json` תחת `groups/711/`. זו העתקה יזומה לקבוצה אחת בלבד. אין למחוק או לשנות את `group.json`.
5. פתחי `/group/711` וודאי שהתוכן, האווטארים והקמע נטענו. החליפי 711 במספר הקבוצה שבחרת, מתוך הרשימה המותרת.

זו פעולת תחזוקה חד־פעמית ב־R2, לא פיצ'ר ייבוא באתר. אם קיימים רק נתונים ישנים בדפדפן ולא ב־R2, אין לאפס או למחוק אותם; העברה שלהם מצריכה חילוץ מתואם בנפרד.

## בדיקות ומפת קבצים

```bash
npm run typecheck
QUEENB_LOCAL_STORAGE=1 npm test
npm run test:storage
```

הבדיקות משתמשות ב־Miniflare מקומי ואינן משנות את ה־bucket האמיתי. הן מכסות את המיפוי המדויק, מסך הכניסה, הפרדת תוכן ותמונות וקמע, שימור הקובץ הישן, קבוצה ריקה, ETag ושמירות מתחרות, קוד שגוי, session מזויף/פג תוקף, rate limit וחסימת ה־AI לפני אימות. בדיקות ה־AI משתמשות במודל מדומה ולא צורכות יצירה אמיתית.

- `app/page.tsx` — בחירת אזור וקבוצה; `app/group/[groupId]/page.tsx` — כניסה ישירה ובדיקת מספר.
- `app/group-app.tsx` — רכיבי האתר המקוריים, משותפים לכל הקבוצות; `app/globals.css` ו־`app/layout.tsx` — תוספות עיצוב וכותרת כללית.
- `lib/groups.ts` — מיפוי הקבוצות ואימות המזהים.
- `lib/storage/*` — סכמת JSON, תמונות מבודדות לכל מופע קבוצה ותור שמירה; `worker/site-data.ts` — מפתח R2 לפי קבוצה.
- `lib/auth/*`, `worker/auth.ts`, `worker/group-api.ts`, `worker/index.ts` — חלונית קוד, session, הרשאות ושער API.
- `app/api/avatar/route.ts`, `app/api/mascot/route.ts`, `lib/ai/index.ts`, `lib/ai/cloudflare-provider.ts`, `workers/flux-image-worker/src/index.js` — הגנת יצירה ותקשורת שרת־לשרת.
- `vite.config.ts`, `.dev.vars.example`, `.gitignore`, `types/cloudflare-env.d.ts`, `worker-configuration.d.ts` — bindings, secrets וטיפוסי Worker. טיפוסי runtime נוצרו עם Wrangler.
- `tests/*.test.mjs`, `package.json` — בדיקות ופקודות בדיקה מעודכנות.
